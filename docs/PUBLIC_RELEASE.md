# 公开发布检查清单

此文档用于发布源码，不授权自动提交、推送、创建公开仓库或发布容器镜像。

## 内容检查

- [ ] 文档使用 `~/h3-service`、`<DGX_LAN_IP>` 等通用示例，没有个人用户名、工作盘路径或真实内网地址。
- [ ] 运行时 `/srv/h3`、`/opt/h3-api` 是约定的部署路径，可以保留；它们不是维护者个人目录。
- [ ] 只保留公开、安全的测试输入。历史测速示例为玩具车提示词；自己的日志和摘要需另外脱敏。
- [ ] `.env.example` 只有占位符；真实 `.env`、API key、HF token、SSH/其他私钥不在源码或文档里。
- [ ] 没有证书、权重、视频、数据库、缓存、模型/镜像备份或嵌套的旧仓库。
- [ ] 附件和 `dist/` 安装包重新生成并检查，不能把旧版本压缩包自动视为已经脱敏。

可以在本地检查当前候选文件和暂存区：

```bash
git status --short --untracked-files=all
git diff --cached --name-only
git diff --cached
git log --all --oneline
```

新仓库未建立首个提交时，`git log` 提示没有提交是正常的。
已有提交历史的仓库，必须另外审查所有历史、分支、标签和远程发布附件。
建议在推送前运行维护中的密钥扫描工具；扫描工具与忽略规则都不能替代人工审查。
不要为了让检查通过而将真实秘密加入扫描白名单。

## 许可与项目定位

- [ ] 保留 `LICENSE` 的上游版权声明和 `NOTICE.md` 的来源，不把上游作者改成自己。
- [ ] 明确社区维护、非 NVIDIA/MiniMax 官方项目，不提供官方兼容性或服务保障。
- [ ] 本仓库源码许可不覆盖 MiniMax 模型、LoRA、CUDA 镜像和其他依赖；使用前审阅各自许可。
- [ ] 下载脚本只引用上游文件，不把权重重新上传到代码仓库或 Release。
- [ ] 性能数字标明硬件、参数、单次测量以及历史基线的限制，不承诺所有机器达到同一速度。
- [ ] 4/8 次的历史 GPU 横评与正式 API、从零构建、自定义次数等尚待验收项清楚区分。

## 发布前验证

```bash
uv sync --extra test --frozen
uv run pytest -q
uv run ruff check .
```

Compose 配置校验需要本地实际 `.env` 或仅用于校验的占位密钥，不应公开完整展开后的配置。
Windows/x86 仅做 CPU/配置检查；ARM64 镜像构建、GPU 运行验证在 DGX 上执行。

按 `scripts/package.ps1` 重新打包后，检查 `tar -tzf dist/h3-api-dgx.tar.gz`。
发布的每一个附加文件都要单独审查；忽略 Git 的 `dist/` 不会阻止手动上传含秘密的附件。
