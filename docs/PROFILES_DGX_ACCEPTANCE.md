## 服务与兼容性

- 一条持久队列、一个 GPU 模型进程组；切换先退出旧进程组，再加载下一配方。
- 最终驻留 Larry，GPU 仅见一个推理 scheduler；没有定时空闲卸载功能。
- 原 309 个完成任务保留，抽查历史状态和视频下载成功。最终 313 个完成任务，1 个失败记录保留。
- LightX2V 非 4 步请求返回 422，不进入队列；配方目录、任务响应、就绪状态通过检查。
- 原模型、LoRA、证书、旧安装目录与旧镜像保留；升级前 SQLite 一致性备份和旧配置备份仅在 DGX 私有目录保存。
- 正式运行目录 `~/h3-service-profiles`；管理时必须使用两个 Compose 文件，见 [使用说明](PROFILES.md)。

## 首轮发现并修复的问题

第一轮 Larry 完成后，切换因端口探测遇到 Linux TCP TIME_WAIT 而误报
`Address already in use`；新模型尚未启动。该失败任务和日志保留，未删除或伪装为成功。
POSIX 探测加入 `SO_REUSEADDR`，不使用 `SO_REUSEPORT`。DGX 上实测验证：
旧探测能复现 TIME_WAIT 误报、新探测通过，而真正存活的监听者仍被拒绝。
修复后从头重跑上述完整三段流程，全部成功。
